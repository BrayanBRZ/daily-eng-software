 ------------------------------------------
 DEFINIÇÃO DE FASES
 ------------------------------------------
 ------------------------
 Fase 1 – Rastreabilidade


 - Atribuição de códigos únicos e criação de um mapa de conexão entre requisitos principais e específicos
 - Garantir que todos os requisitos sejam identificados de forma única e rastreável, evitando confusões e facilitando a gestão do projeto
 ------------------------
 Fase 2 – Identificação do Requisito Principal


 - Definir claramente as necessidades principais que o sistema deve atender, estabelecendo uma base sólida para o desenvolvimento dos requisitos detalhados
 - Identificação e documentação dos requisitos principais do sistema, com foco no que é essencial para o sucesso do projeto
 ------------------------
 Fase 3 – Especificação


 - Transformar os requisitos principais em requisitos específicos e detalhados, descrevendo as funcionalidades e comportamentos de forma clara e precisa
 - Decomposição de requisitos principais em requisitos mais específicos, com um nível de detalhamento adequado para guiar o desenvolvimento
 ------------------------
 Fase 4 – Identificação dos Atores


 - Definir quem são os usuários ou sistemas que irão interagir com o sistema e como essas interações serão feitas
 - Identificação dos diferentes tipos de usuários e suas interações com os requisitos específicos do sistema
 ------------------------
 Fase 5 – Complementação Funcional


 (Adição de funcionalidades complementares que agregam valor ao sistema e atendem a necessidades adicionais que podem não ter sido consideradas nas fases anteriores)
 - Adicionar funcionalidades extras que atendam a necessidades complementares, melhorando a experiência geral ou a performance do sistema
 - Identificação e documentação de funcionalidades adicionais, que não eram inicialmente previstas, mas são relevantes para o sistema
 ------------------------
 Fase 6 – Funcionalidades Fora do Escopo Inicial


Inclusão de funcionalidades que vão além do escopo inicial do projeto.
Embora essas funcionalidades não sejam necessárias para o lançamento ou entrega imediata do sistema, elas podem ser consideradas de valor para o produto final.
Essas funcionalidades geralmente são ideias que surgem durante o processo de desenvolvimento ou feedback de usuários e stakeholders.


- Identificar e adicionar funcionalidades que não estavam no escopo original, mas que podem ser valiosas para o sistema
- Definição de funcionalidades que ficam fora do escopo inicial, mas que podem ser consideradas para inclusão em versões futuras ou como extras
------------------------
Fase 7 – Validação e Verificação


- Validar e verificar que todos os requisitos foram corretamente implementados e que o sistema funciona conforme o esperado
- Realização de testes, revisões e validações para garantir que todos os requisitos foram atendidos e que o sistema está pronto para ser entregue
 


-----------------------------------------
LEVANTAMENTO DE REQUISISTOS (Baseado na aula passada)
-----------------------------------------
------------------------
1. Cadastro de Usuários
   
Requisitos Principais:
[LRP001] O sistema deve permitir o cadastro de diferentes tipos de usuários (Aluno, Professor, Funcionário, etc.)
[LRP002] O sistema deve ser capaz de gerar um número de identificação único para cada usuário


Requisitos Específicos:
[LRE001] Permitir a inserção do nome do usuário
[LRE002] Permitir a escolha do tipo de ocupação do usuário (Aluno, Professor, Funcionário, etc.)
[LRE003] Permitir a inserção do número de matrícula para alunos, ou um campo genérico para outros tipos de ocupação
[LRE004] Permitir a inclusão de uma avaliação ou histórico de empréstimos do usuário (Nota)
[LRE005] Permitir a inserção do e-mail para comunicação e alertas
[LRE006] Permitir a inclusão de número de telefone para contato emergencial
[LRE007] Permitir a definição do status do usuário (Ativo, Suspenso, Inativo)


------------------------
2. Cadastro de Equipamentos


Requisitos Principais:
[LRP003] O sistema deve permitir o cadastro de equipamentos, com um identificador único para cada item


Requisitos Específicos:
[LRE008] Permitir a inserção do nome do equipamento
[LRE009] Permitir a definição da classe do equipamento (ex: Instrumento musical, Calculadora, etc.)
[LRE010] Permitir a descrição detalhada do equipamento
[LRE011] Permitir o controle do estado de conservação do equipamento (Novo, Usado, Danificado, etc.)
[LRE012] Permitir a inclusão da localização onde o equipamento está armazenado
[LRE013] Permitir a inclusão de uma avaliação do estado do equipamento ou histórico de manutenção (Nota)
[LRE014] Permitir a categorização do equipamento (Tecnologia, Mobiliário, Instrumentos, etc.)
[LRE015] Permitir o registro da data de aquisição do equipamento
[LRE016] Permitir o acompanhamento do histórico de manutenção do equipamento (se houver)


------------------------
3. Cadastro de Locais
   
Requisitos Principais:
[LRP004] O sistema deve permitir o cadastro de locais, com identificador único e detalhes relacionados à capacidade e equipamentos disponíveis


Requisitos Específicos:
[LRE017] Permitir a inserção do nome do local (ex: Auditório, Sala de Reuniões, etc.)
[LRE018] Permitir a inserção da localização do local (ex: Bloco A - Sala 101)
[LRE019] Permitir a definição da capacidade máxima de pessoas no local
[LRE020] Permitir o registro dos equipamentos disponíveis no local
[LRE021] Permitir o controle do estado de conservação do local (ex: Limpeza, Manutenção, etc.)
[LRE022] Permitir a avaliação do estado do local (Nota)
[LRE023] Permitir a inserção dos horários de funcionamento do local, se relevante
[LRE024] Permitir a definição de regras específicas para o empréstimo do local (se houver)


------------------------
4. Controle de Equipamentos Emprestados
   
Requisitos Principais:
[LRP005] O sistema deve permitir o controle de empréstimos de equipamentos, com registro de todos os detalhes do empréstimo


Requisitos Específicos:
[LRE025] Permitir a criação de um número de identificação único para cada empréstimo
[LRE026] Permitir a associação do empréstimo com o número de identificação do usuário
[LRE027] Permitir a associação do empréstimo com o número de identificação do equipamento
[LRE028] Permitir a definição da data de requisição do empréstimo
[LRE029] Permitir a definição da data de devolução prevista do equipamento
[LRE030] Permitir o registro da data de devolução efetiva do equipamento
[LRE031] Permitir o registro do estado de conservação do equipamento no momento da devolução
[LRE032] Permitir a avaliação do estado do equipamento na devolução (Nota)
[LRE033] Permitir o controle do status do empréstimo (Ativo, Concluído, Atrasado, Cancelado, etc.)
[LRE034] Permitir a inclusão de um campo opcional para o motivo do empréstimo


------------------------
5. Controle de Locais Emprestados
   
Requisitos Principais:
[LRP006] O sistema deve permitir o controle de empréstimos de locais, com registro de todos os detalhes sobre o empréstimo do espaço


Requisitos Específicos:
[LRE035] Permitir a criação de um número de identificação único para cada empréstimo de local
[LRE036] Permitir a associação do empréstimo com o número de identificação do usuário
[LRE037] Permitir a associação do empréstimo com o número de identificação do local
[LRE038] Permitir a definição da data de requisição do empréstimo do local
[LRE039] Permitir a definição da data e horário do empréstimo do local
[LRE040] Permitir a definição da data e hora de devolução do local (se aplicável)
[LRE041] Permitir o registro do estado de conservação do local na devolução
[LRE042] Permitir a avaliação do estado do local na devolução (Nota)
[LRE043] Permitir o controle do status do empréstimo do local (Ativo, Concluído, Atrasado, Cancelado, etc.)
[LRE044] Permitir a inclusão de equipamentos requisitados para o local, se aplicável
