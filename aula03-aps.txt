RETOMADA
=========================================

O ciclo de vida de software descreve as etapas pelas quais o software passa, desde a sua concepção até a manutenção pós-implantação. Como qualquer projeto, é essencial equilibrar as fases de planejamento e execução para garantir que o desenvolvimento seja bem-sucedido, sem comprometer a qualidade ou o tempo de entrega. A escolha do modelo certo para o SDLC pode otimizar tanto o processo de planejamento quanto a execução.

=========================================
TÉCNICAS DE LEVANTAMENTO DE REQUISITOS
=========================================

-----------------------------------------
1. Entrevistas
-----------------------------------------

Metodologia: Entrevistas com stakeholders para entender necessidades e expectativas. Objetivo: Obter informações detalhadas diretamente dos envolvidos. Vantagens: Insights profundos e flexibilidade. Desvantagens: Demorado e depende da habilidade do entrevistador.

-----------------------------------------
2. Questionários
-----------------------------------------

Metodologia: Aplicação de formulários estruturados para obter dados quantitativos. Objetivo: Coletar respostas rápidas de muitos stakeholders. Vantagens: Eficiência e análise quantitativa fácil. Desvantagens: Pouca profundidade e dificuldade em interpretar respostas vagas.

-----------------------------------------
3. Workshops
-----------------------------------------

Metodologia: Sessões colaborativas com stakeholders para discutir e definir requisitos. Objetivo: Facilitar comunicação e entendimento mútuo. Vantagens: Interatividade e colaboração. Desvantagens: Dificuldade em conciliar agendas e risco de decisões não consensuais.

-----------------------------------------
4. Prototipação
-----------------------------------------

Metodologia: Criação de protótipos para visualizar funcionalidades antes da implementação. Objetivo: Validar requisitos com uma representação tangível. Vantagens: Feedback rápido e identificação precoce de falhas. Desvantagens: Pode gerar expectativas irreais e ser custoso.

-----------------------------------------
5. Análise Documental
-----------------------------------------

Metodologia: Revisão de documentos existentes para entender o contexto atual. Objetivo: Identificar necessidades e requisitos passados. Vantagens: Menor custo e revela requisitos não expressos verbalmente. Desvantagens: Pode estar desatualizado e difícil de extrair informações claras.

=========================================
LEVANTAMENTO DE DADOS VS. ANÁLISE DE DADOS
=========================================

Levantamento de dados refere-se à coleta de informações de diversas fontes, como entrevistas, questionários e observação. É uma etapa inicial que visa reunir dados brutos ne cessários para compreender o contexto de um projeto. Já a análise de dados envolve o estudo detalhado dessas informações coletadas, com o objetivo de extrair conclusões significativas, identificar padrões e tomar decisões informadas para o desenvolvimento do projeto.

=========================================
CONTEÚDO DA AULA DE HOJE
=========================================

-----------------------------------------
• Por qual motivo estudar/entender a evolução do desenvolvimento de software?
	Estudar modelos tradicionais ajuda a entender a evolução do desenvolvimento de software e como abordagens atuais surgiram. Alguns modelos antigos ainda são aplicados em projetos com requisitos bem definidos.
-----------------------------------------
• O que é levantamento de dados? Diferença entre levantamento e análise.
	Levantamento de dados é a coleta de informações, enquanto análise de dados é o estudo e interpretação dessas informações para tomar decisões no projeto.
-----------------------------------------
• Quais são as técnicas de levantamento de requisitos e em que caso utilizar cada uma?

- Entrevistas: Para obter informações detalhadas diretamente dos stakeholders.

- Questionários: Para coletar dados rápidos de muitos participantes.

- Workshops: Para promover colaboração e consenso entre stakeholders.

- Prototipação: Para validar requisitos com feedback visual e funcional.

- Análise Documental: Para revisar informações já existentes e entender o contexto.
